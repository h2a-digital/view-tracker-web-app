# Automatic social profile metadata

Prepared November 9, 2026. No deployment, production database mutation, live creator backfill, reconnection, paid purchase or new OAuth scope is performed during development.

## Provider support

| Provider                              | Endpoint/fields                                                                                          | Requirements/limitations                                                                                                                                                                                                                              |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TikTok through Zernio                 | Existing `GET /api/v1/accounts`: `displayName`, `username`, `profilePicture`                             | Connected account, existing server API key. Profile pictures are nullable and originate from Zernio's platform cache. No additional request is needed during the existing connection callback.                                                        |
| Instagram through Zernio              | Same account response                                                                                    | Existing Professional account connection; the Instagram/Zernio feature flag is respected.                                                                                                                                                             |
| Instagram Meta Unified/Facebook Login | `GET https://graph.facebook.com/{version}/{connected_ig_id}?fields=id,username,name,profile_picture_url` | Existing authorized Instagram asset/basic permission. Exact returned immutable ID must match. Unified Login's existing endpoint allowlist is extended only for these exact fields on the connected IG ID, never messages or unrelated assets.         |
| Legacy Instagram Login                | `GET https://graph.instagram.com/{version}/me?fields=user_id,username,name,profile_picture_url`          | Existing `instagram_business_basic` grant; no additional scopes. A revoked grant still follows the existing deletion policy.                                                                                                                          |
| YouTube official                      | Existing `channels.list`/OAuth/daily identity response                                                   | Existing title/handle/avatar cache remains compatible. Unconnected registrations can use public metadata through an existing valid YouTube grant or optional `YOUTUBE_DATA_API_KEY`. Public metadata never verifies ownership or connects an account. |
| Official TikTok                       | Documented `/v2/user/info/` field `avatar_url` uses `user.info.basic`                                    | The actual official integration is stashed and absent from the checked-out application. It is not restored, enabled or reimplemented here. Its avatar is a documented future capability, not a live-supported integration in this checkout.           |

References: [Zernio account schema](https://docs.zernio.com/accounts/list-accounts) (the official page's SocialAccount schema explicitly defines nullable `profilePicture`), [Meta IG User reference](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/), [Meta's official generated SDK field definitions](https://github.com/facebook/facebook-python-business-sdk/blob/main/facebook_business/adobjects/iguser.py), [official TikTok fields](https://developers.tiktok.com/docs/en/tiktok-api-v2-get-user-info). Meta's documentation website rate-limited this audit; the SDK confirms `name`, `username`, `profile_picture_url`, but successful responses under the deployed grant must still be checked live. No Meta App Review or scope change is introduced.

## Automatic lifecycle

- YouTube retains registration-time public lookup and OAuth metadata capture. TikTok/Instagram metadata cannot be anonymously discovered reliably by handle through these integrations: those registrations acquire provider details when the creator connects.
- Zernio connection callbacks reuse the already-fetched account object. Meta connection callbacks make one best-effort, bounded profile request after identity verification; failure does not fail OAuth or erase the previous cached profile.
- Profiles refresh approximately every **24 hours**. Existing YouTube daily source checks already refresh channel identity; the profile scheduler recognizes that fresh cache and avoids a duplicate metadata API call.
- The existing authenticated five-minute worker handles **one due profile per invocation**, after video work and only with at least 6.5 seconds of provider budget left. Profile requests receive at most six seconds of that budget. Existing missing profiles backfill across successive ticks; slow tracking can defer metadata work. A new private lease row prevents concurrent profile refreshes. No new cron, external queue or polling service is introduced.
- Temporary failures retain valid cached name/avatar data, record a separate profile status and retry after **one hour**. Per-account manual refresh in **Details → Refresh profile details** remains available with a one-minute cooldown. Metadata failure does not turn a successful video synchronization into an error or affect compensation eligibility.
- Metadata is in existing `accounts.integration` JSON. Updates are fenced by provider, registered username, immutable connected ID and lease, and cannot restore source-erased/archived records. Existing direct-provider erasure removes profile metadata. The existing retention sweep expires unrevalidated profile caches after 29 days, preserving account registration and other data.
- Profile fields are presentation-only. Registered/verified identifiers, campaign mappings, metrics, snapshots, tracking windows and financial calculations are unchanged.

## Avatars and layout

Pictures are browser-loaded HTTPS URLs from known platform/CDN hosts, without referrers or credential-bearing query parameters; no server-side avatar downloads, scraping, storage bucket or proxy is added. Missing, expired or inaccessible images show circular platform-icon fallbacks. The avatar retries on a subsequent metadata refresh even if the provider returns the same URL. Zernio may continue returning an expired upstream URL until its own cache refreshes; no real-time URL availability guarantee is made.

The Social Accounts grid has a maximum of **three desktop columns (1280px+)**, **two tablet columns (768–1279px)**, and **one mobile column**. Grid rows stretch to the tallest card, natural warning text determines row height, and actions align at the bottom. Names truncate and handles/routing text wrap; no fixed oversized card height is used.

The global YouTube refresh button is removed. Profile metadata is never fetched from account-card renders or ordinary workspace GET refreshes. The legacy YouTube metadata endpoint remains compatible for existing callers, but the UI uses the shared per-account profile endpoint.

## Deployment

1. With the already-applied `202611090002_youtube_channel_metadata.sql`, manually apply **`supabase/migrations/202611090003_social_profiles.sql`** once. Schema version remains 5. It creates only private metadata lease bookkeeping and service-only functions, and wraps the existing retention sweep without changing its existing source/grant policy. Applying it deletes no existing records and changes no provider connections. It briefly locks workspace revision metadata; avoid administrative writes during the migration.
2. No new environment variables or provider configuration are required. Keep all current credentials, `ZERNIO_INSTAGRAM_ENABLED` and organic-verification flags unchanged. The existing optional YouTube public API key remains optional.
3. Deploy manually. Let existing Supabase Cron run. Check the worker response's separate `profileMetadata` status and account Details' last profile attempt. Initial backfill can take several five-minute ticks; browser-only local development needs worker execution because no local scheduler is added.
4. Validate a real Zernio TikTok avatar, each Instagram connection method actually in use, URL-error fallback and the grid at desktop/tablet/mobile sizes. Confirm captions/views/payouts and all connected identities remain unchanged. Provider payload tests and disposable PostgreSQL are not a live entitlement or browser-layout test.
